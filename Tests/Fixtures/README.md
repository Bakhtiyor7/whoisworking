https://code.claude.com/docs/en/hooks (Claude Code 2.1.329/2.1.330 era). They are
**not** captured from a live session. Replace or extend them with captured payloads
when available (run WhoIsWorking with `WHOISWORKING_LOG_EVENTS=1` and copy files from
`~/Library/Application Support/WhoIsWorking/event-log/`).

## `opencode-real/` (CAPTURED, anonymized)

Captured on 2026-11-22 from OpenCode CLI 2.0.14 (`opencode run --standalone`, free model
`tidepool-alpha-free`) with a capture plugin in a scratch project. Four runs: `run1` a plain reply,
`run2` a shell command, `run3` a permission request that OpenCode rejected, `run4` a subagent.

- `runN.jsonl`: the captured events, one per line, filtered to the session, permission and form
  types the plugin reads. Paths are `/Users/me/dev/demo`; session, message, call, permission and
  event ids are numbered placeholders; prompt text, reasoning, tool output, snapshots and token
  counts are removed. The shell command in `run2` was changed to `echo hello`.
- `sessions.json`: what `ctx.session.get` returned for those sessions, anonymized the same way.
- `e2e-permission.forwarded.jsonl`: CAPTURED on 2026-11-22 from the shipped plugin itself, loaded by
  OpenCode 2.0.14 in a scratch project, with a socket listener standing in for WhoIsWorking: a
  permission request that OpenCode rejected. Ids and the folder are anonymized as above.
- `runN.forwarded.jsonl`: what WhoIsWorking's plugin sends for each run. Generated by running
  `OpenCodePlugin.contents` under Node over `runN.jsonl` and `sessions.json`;
  `OpenCodePluginTests/forwardsTrimmedEventsInOrder` checks that the plugin still produces them.
